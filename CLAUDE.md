# CLAUDE.md

MiB-SQL: IDE educativo per MariaDB/MySQL su Linux ispirato a dbForge Studio. Progetto autonomo (nessun codice condiviso con LinBI). UI in italiano e inglese.

## Comandi

```bash
npm run dev         # Vite :5174 + Electron (VITE_DEV=1)
npm run build       # renderer in dist/
npm test            # node --test tests/*.test.cjs
npm run typecheck   # tsc --noEmit (solo src/)
npm run dist        # AppImage + .deb
```

## Architettura

- `electron/main.cjs` — accelerazione GPU spenta di default dalla 1.4.1 (finestra nera con alcuni driver, nessun crash da intercettare: `--enable-gpu` / `MIBSQL_ENABLE_GPU=1` la riattivano); finestra, IPC (`handle()` → `{ok}`/`{error, code}`), dialog file. Menu applicazione rimosso; F12 = DevTools.
- `electron/connections.cjs` — profili in `<userData>/connections.json`; segreti in `secrets.json` cifrati con `safeStorage` async. Backend `basic_text` = portachiavi non disponibile → segreti solo in memoria per la sessione.
- `electron/server.cjs` — per connessione: pool metadati (explorer, completamento, `KILL QUERY`) + tunnel SSH condiviso (`ssh2`, server locale su porta 0). Per documento: connessione dedicata (sessione). `exec()` divide lo script, esegue in sequenza, normalizza celle (BigInt/DECIMAL → stringa, Buffer → `0x…`, JSON → stringa), limita a 50.000 righe per resultset. `open()` prova prima una connessione singola: il pool riproverebbe fino ad `acquireTimeout` perdendo il codice d'errore.
- `electron/sqlsplit.cjs` — splitter tipo client mariadb (quote, commenti, `DELIMITER`), offset sul testo originale; `scan(text, delim, final)` e `Splitter` incrementale per i file grandi; `isBlank` è uno scanner (le regex con `\s` mangiavano le righe dopo `--`). Testato in `tests/`.
- `electron/explorer.cjs` — query su `information_schema`, `SHOW CREATE` per i DDL.
- `electron/export.cjs` — writer CSV/JSON/SQL/xlsx (exceljs in streaming) riga per riga; `server.streamQuery` per esportare tutta una query. `server.apply` esegue le modifiche della griglia in transazione su una connessione del pool (`expectOne` → rollback sui conflitti), `server.selectRows` rilegge le righe toccate.
- `src/store.ts` — zustand: profili, stato connessioni, cache metadati (`metaKey`), documenti, dialog. `openConn` gestisce il prompt password su errori di autenticazione.
- `src/editor.ts` — Monaco: un modello per documento, dirty per `alternativeVersionId`, completamento (alias via `tableRefs`), marker errori.
- `src/edits.ts` — logica pura delle modifiche in griglia (target modificabile, `Edits`, generazione UPDATE/INSERT/DELETE parametrizzati, anteprima). Testata da `tests/edits.test.mjs` con il type stripping di Node: `src/package.json` dichiara `"type": "module"` per questo.
- `src/design.ts` — modello del designer tabelle (`TableDef`, colonne/indici/FK con id stabili), `createSql`, `alterSql` per differenza (FK modificate in un ALTER a parte, posizioni simulate nell'ordine delle clausole, RENAME per ultimo), `validate`. Test: `tests/design.test.mjs`; verificato anche contro MariaDB 10.11/11.4 e MySQL 8.4. `explorer.tableDefinition` legge la struttura (COLUMN_DEFAULT è un'espressione su MariaDB, su MySQL viene quotato), `server.runStatements` esegue il DDL.
- `src/components/TableDesigner.tsx` — documento `kind: 'table'` (Doc.design.table, null = nuova); stato in `designByDoc` (store.ts). Le schede designer si ripristinano dal server, senza le modifiche non applicate.
- `src/er.ts` + `components/ErDiagram.tsx` — diagramma ER (doc `kind: 'er'`): modello da `explorer.erModel` (3 query su tutto lo schema), layout a livelli con padri avvicinati ai figli, SVG con stili interni (variabili CSS con fallback chiaro: gli export restano chiari). Editor visuale: relazioni trascinate tra righe `[data-col]`, DDL via `api.ddl.run`. Disposizione per conn/db in localStorage.
- `src/qb.ts` + `components/QueryBuilder.tsx` — query builder (doc `kind: 'query'`, modello in `doc.qb`, persistito con le schede). `runDoc` per i doc query rigenera l'SQL con `toSql` nel modello Monaco del documento e riusa sessione e ResultsPanel.
- `src/compare.ts` + `components/CompareView.tsx` + `electron/datacompare.cjs` — confronto (doc `kind: 'compare'`, origine/destinazione in `doc.cmp`). `explorer.schemaSnapshot` = `tableDefinitions` (5 query per tutto lo schema) + DDL normalizzate (senza DEFINER/schema) di viste e routine; `alignTo` dà alla definizione d'origine gli id della destinazione per nome, poi `alterSql`. `syncStatements`: DROP/CREATE TABLE con FOREIGN_KEY_CHECKS=0, tutto il resto (FK comprese) con i controlli attivi, perché MariaDB salva come NO ACTION le regole RESTRICT aggiunte a controlli spenti. Dati: origine a blocchi di 5.000 per PK (keyset, predicato espanso per chiavi composte), righe della destinazione nello stesso intervallo in streaming (intervalli valutati dal server: collation corrette), memoria costante; istruzioni parametrizzate (`UNHEX(?)` per i binari) eseguite con `server.apply`.
- `electron/backup.cjs` — dump proprio (pool conn in UTC, `SHOW CREATE`, INSERT a blocchi con `export.literal`, trigger dopo i dati, DELIMITER ;;) e restore a flusso con `Splitter` (sqlsplit.cjs). Il restore è byte-transparent: file letto come latin1, connessione dedicata (`server.withDedicated`) con collation latin1, `session_track_system_variables = ''` (altrimenti il driver torna a UTF-8 vedendo SET NAMES) e poi `SET NAMES utf8mb4`.
- `electron/importer.cjs` + `components/TaskDialogs.tsx` — import CSV/xlsx/JSON (CsvParser a flusso, exceljs WorkbookReader), `normalize`/`inferType`, tutto in una transazione; dialoghi Backup/Ripristino/Import aperti da `store.task`. Aggancio test `MIBSQL_OPEN=<file>` salta il dialog di apertura.
- Fase 8: `server.profile` (status prima/dopo meno il costo di SHOW STATUS, SHOW PROFILE, ANALYZE FORMAT=JSON solo per letture) + `src/profile.ts` (planRows, hints) + `ProfileView` nella scheda «Profilo»; `server.monitorSnapshot` (query marcate `/* mibsql-monitor */` e nascoste dalla lista) + `src/monitor.ts` (ratei) + `Monitor.tsx` (grafici a una serie, colore `--series` validato con lo skill dataviz); `explorer.users/grants` + `src/users.ts` (parseGrants, grantStatements, maskPasswords) + `Users.tsx`. Doc `kind: 'monitor' | 'users'` aperti con `openServerTool`.
- `allowPublicKeyRetrieval` è attivo solo senza SSL: serve a MySQL 8 (caching_sha2_password) al primo login di un account.
- v1.0: `exec` usa `queryStream` per le istruzioni di sola lettura (READ_ONLY in server.cjs) e tiene al massimo MAX_ROWS righe contando le altre; chiusura finestra: main intercetta `close` → `requestQuit` (actions.ts) → `api.confirmClose()`; binari in griglia via `UNHEX(?)` (edits.ts) con caricamento/salvataggio da file (`file:readHex/writeHex`); CHECK di colonna/tabella e indici DESC nel designer (`check` in DColumn, `checks` in TableDef, `desc` nelle colonne indice); colonne spaziali scritte nel dump come `ST_GeomFromWKB(…, srid)`.
- Assistente AI: `electron/assistant.cjs` (SDK `@anthropic-ai/sdk` 1.x, `client.beta.messages.stream`, `claude-opus-5-5` predefinito, effort esplicito, `fallbacks: "default"` + beta `server-side-fallback-2026-07-01` per Opus/Sonnet 5.5, errori per classe SDK, chiave in safeStorage o credenziali di sistema) + `src/assistant.ts` (SYSTEM_PROMPT, `schemaText`, `userMessage`, `parseBlocks`) + `components/AssistantPanel.tsx`. Conversazione append-only per documento (contenuto completo dell'assistente, blocchi thinking compresi), system con lo schema congelato a inizio chat (cache_control sullo schema): non modificare mai i turni già inviati. Test senza credenziali: server finto SSE su `ANTHROPIC_BASE_URL` (l'SDK 1.x manda la chiave d'ambiente come `Authorization: Bearer`).
- Partizioni nel designer: `Partitioning` in TableDef, `partitionStatements` (PARTITION BY / REMOVE / DROP+ADD in coda / REORGANIZE), ognuna in un ALTER separato; sottopartizioni mai alterate.
- Pacchetto: `npm run dist` produce AppImage e .deb (StartupWMClass `mib-sql`); il .deb è verificato con apt in un container ubuntu:24.04 + xvfb.
- v1.2: `src/format.ts` (formattatore a token, puro: `tokenize`, `formatSql`, `signature`; mai cambiare le maiuscole di parole in posizione di nome tabella/alias; test di invarianza dei token e idempotenza in `tests/format.test.mjs`), opzioni in localStorage e provider Monaco in `editor.ts`. `electron/library.cjs`: cronologia (`history.jsonl`, append, compattata oltre 5.000) e snippet (`snippets.json`, assente = predefiniti; sintassi snippet Monaco, `\$` letterale); registrazione in `recordHistory` (actions.ts) con `maskPasswords`. Editor oggetti = documento SQL con `doc.obj` (`openObject`/`applyObject`/`dropObject`, ObjectBar): `electron/objects.cjs` (`header`, `statementOf`, OR REPLACE su MariaDB e viste, altrimenti DROP+CREATE con ripristino; connessione dedicata sul database). `src/routines.ts` (`callScript`) + CallDialog. `electron/maint.cjs` (stats da TABLES, operazioni una tabella alla volta, progress `task:progress`) + `Maint.tsx`. Le connessioni hanno `rowsAsArray: true` di default: per leggere per nome colonna passare `rowsAsArray: false`.
- v1.3: `electron/procs.cjs` (snapshot di PROCESSLIST, INNODB_TRX, lock di riga — INNODB_LOCK_WAITS/INNODB_LOCKS su MariaDB, performance_schema.data_lock_waits/data_locks su MySQL — e metadata lock, METADATA_LOCK_INFO su MariaDB, metadata_locks su MySQL; ogni fonte facoltativa finisce in `missing`), `src/procs.ts` (`waits`, `rootBlockers`, `idleInTrx`, `summary`, `latestDeadlock` per i due formati di SHOW ENGINE INNODB STATUS, fixture in tests/fixtures) + `ProcessManager.tsx` (doc `procs`). `electron/perf.cjs` (overview = SHOW GLOBAL STATUS/VARIABLES + aggregati di information_schema, `topQueries` da events_statements_summary_by_digest o mysql.slow_log, `indexData` con l'uso da table_io_waits_summary_by_index_usage o userstat, `setVariable`, `explain` su connessione dedicata) + `src/advisor.ts` (regole), `src/indexes.ts`, `src/queryadvisor.ts` (legge la query con il tokenizer del formattatore: tabelle/alias, predicati, lint, indici suggeriti; `normalizeSql`/`groupSlowLog` per lo slow log), `src/variables.ts` + `Performance.tsx` (doc `perf`, `doc.perf.tab/sql/db`; «Analizza e ottimizza query» nell'editor apre la scheda Ottimizza). `electron/datagen.cjs` + `src/datagen.ts` (generatori per colonna, `guess`, rng seminato per tabella.colonna, unicità per colonna e per chiave composta, `insertOrder`) + `DataGenerator.tsx` (doc `datagen`, impostazioni in `doc.datagen`, inserimento a blocchi con `server.apply`). `src/docgen.ts` (HTML autonomo con `erSvg` e Markdown) + `DocGenerator.tsx` (doc `docgen`). Strumenti server (`perf`, `procs`, `monitor`, `users`) aperti con `openVisual`: senza connessione aperta TargetDialog chiede solo la connessione (`SERVER_KINDS`). - v1.4: `electron/search.cjs` (oggetti: LIKE su information_schema, poi `src/search.ts` filtra maiuscole/parola intera e trova la riga; dati: una tabella alla volta, colonne di testo e numeriche, chiave primaria nel risultato, stop) + `Search.tsx` (doc `search`, `doc.search`). `electron/logs.cjs` (errori da performance_schema.error_log, file `log_error` letto direttamente se la connessione è locale e non SSH, altrimenti LOAD_FILE, journal con `journalctl -u mariadb -o short-iso`; slow/general da tabella o file) + `src/logs.ts` (parser con fixture reali di MariaDB 11.4 e MySQL 8.4 in tests/fixtures) + `Logs.tsx` (doc `logs`). `electron/copydb.cjs` = `backup.dump` in un .sql.gz temporaneo + CREATE DATABASE con charset/collation dell'origine + `backup.restore` (il dump usa nomi non qualificati) + `CopyDialog` in TaskDialogs (task `copy`). `electron/updates.cjs`: ultima release da api.github.com (`MIBSQL_UPDATE_FEED` per i test, con http ammesso), `APPIMAGE` → scarica accanto e rinomina sopra, /opt → `pkexec apt-get install`, poi `app.relaunch`; `src/components/Updates.tsx` (barra, finestra, controllo all'avvio ogni 12 h in localStorage `mibsql.updates`); versione nel renderer con `__APP_VERSION__` (define di Vite). Generatore: chiavi esterne composte con `fk.group`/`fk.index` e `fkTuples` (`datagen:rowsOf`). `server.open`/`openSession` riprovano senza database se quello predefinito del profilo non esiste più (errno 1049).
- Multilingue: `src/i18n.ts` (`t`, `tn`, `locale()`, lingua in localStorage `mibsql.lang`, iniziale dalla lingua del sistema) ed `electron/i18n.cjs` (stessa logica, lingua comunicata dal renderer con `app:setLang`). I testi si scrivono in italiano dentro `t('…')` con segnaposti `{0}`; `locales/en.json` è il dizionario (chiave = testo italiano). `scripts/i18n-keys.mjs` estrae le chiavi da `t`/`tr`/`tn` (solo letterali: niente chiavi composte a runtime) e `tests/i18n.test.mjs` fallisce se ne manca una o i segnaposti non coincidono. Nei file con variabili locali chiamate `t` si importa `t as tr`. Le conferme (`api.confirm(t('…'), t('…'), [t('…')])`) e il JSX passato come proprietà (`buttons={<>…</>}`) vanno tradotti come il resto. Cambiare lingua ricarica la finestra (`switchLanguage`: salva le schede, riapre le connessioni aperte): le costanti del renderer con `t()` a livello di modulo vanno bene, quelle del processo principale no (il modulo si carica prima di `app:setLang`): lì servono funzioni. Numeri e date con `locale()`, mai 'it-IT' fisso.
- `src/theme.ts` — tema: `<html data-theme>` + variabili in `styles.css` (`:root` chiaro, `:root[data-theme="dark"]` scuro), temi Monaco `mibsql`/`mibsql-dark`, preferenza light/dark/system in localStorage; nei componenti usare sempre le variabili (`--panel`, `--input`, `--subtle`, `--line`…), mai colori fissi.
- `src/components/ResultView.tsx` — barra filtri/modifiche/export sopra `ResultGrid`; modifiche in sospeso in `editsBySet` (WeakMap per ResultSet, store.ts). `runDoc`/`closeDoc` chiedono conferma se ci sono modifiche non applicate.
- `src/actions.ts` — azioni documento (run, cancel, save, DDL, select top), persistenza schede in localStorage.
- `src/components/` — `Explorer`, `SqlEditor` (un'unica istanza Monaco, swap modelli), `ResultsPanel`, `ResultGrid` (virtualizzata, righe 22px), `Dialogs`, `ContextMenu`, `Icon` (SVG inline).

## Test e screenshot

- `MIBSQL_USERDATA=<dir>` usa un profilo separato (mai il profilo reale nei test).
- `MIBSQL_SHOT=out.png MIBSQL_SCRIPT=script.js [MIBSQL_WAIT=ms]`: esegue lo script nel renderer, salva il valore restituito in `out.json`, cattura e chiude. Lo script usa `window.__mib = { useStore, actions, monaco }`.
- `MIBSQL_SAVE_AS=<path senza estensione>` salta il dialog di salvataggio degli export.
- `MIBSQL_CONFIRM=0,1,…` risponde alle conferme native in ordine (indice del pulsante) e le stampa su stdout.
- `MIBSQL_LOG=1` copia la console del renderer su stdout.
- Per gli screenshot pubblici usare il MySQL in docker (`mysql:8.4`) o l'utente `mibsql`: con root sul MariaDB locale i consigli elencano tabelle dei db `r_lab_*`.
- Nei test UI: React 19 applica lo stato in un microtask, quindi tra eventi sintetici consecutivi (mousedown → contextmenu) serve un `await sleep()`.
- DB di prova: `scripts/demo.sql` → `mibsql_demo` + utente `mibsql`/`mibsql` limitato a quel db. Non usare i db `r_lab_*` per i test.
- Tunnel SSH verificato con container `mariadb:11.4` + `linuxserver/openssh-server` sulla stessa rete Docker.
